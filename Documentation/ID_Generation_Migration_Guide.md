# ID Generation Migration Guide

## Overview

All human-readable record identifiers across **Platform** (`public` schema) and **Simulator** (`sim` schema) are now generated by the **Admin-managed** `admin.id_generation_rules` engine via `admin.generate_display_id()`.

Legacy per-table `generate_*_identifier()` functions and **BEFORE INSERT** triggers have been retired in favour of a single **AFTER INSERT** pattern.

**Companion Admin work:** `E:\project-nidus-admin\SQL\v155` (sequential engine), `v156` (entity rules seed).

## Architecture

```
INSERT row → AFTER INSERT trigger → admin.generate_display_id('schema.table', id)
                                 → UPDATE schema.table SET identifier_column = display_id
```

Rules are configured in the Admin app (**System → ID Generation Rules**) or seeded via `v156_id_generation_sequential_entity_rules_seed.sql`.

### Rule modes used in this migration

| Pattern | Example | Rule config |
|---------|---------|-------------|
| Year-scoped global | `RR-2026-001` | `include_date=YYYY`, no scope |
| Year-scoped per register | `R-2026-001` | `include_date=YYYY`, `scope_column=risk_register_id` |
| Project-scoped | `CPR-001` | no date, `scope_column=project_id` |
| Daily ticket | `TKT-20260712-00001` | `date_format=YYYYMMDD`, 5 digits |
| Global sequential | `PORT-0001` | no date, no scope, 4 digits |

## What changed per domain

### Retired (public)
All `generate_*` functions listed in `v755_system_wide_id_generation_migration_plan.md` inventory — replaced by admin engine triggers.

### Integer counters retained
These are **not** display IDs and keep dedicated BEFORE INSERT logic:
- `risks.risk_number`
- `issues.issue_number`
- `lessons_learned.lesson_number`
- `daily_log_entries.entry_number`
- `wp_*_criteria.criteria_number`

### Form instances (Phase 8)
New column `instance_reference` on `public.form_instances` and `sim.form_instances`, format `FI-2026-001` scoped per `project_id`.

### Format notes
Some legacy formats embedded project codes in the middle of the reference (e.g. `CPR-PROJ001-WP01-001`). The admin engine produces **abbreviation + optional date + scoped sequence** (e.g. `CPR-001` per project). Existing values are unchanged; only **new** records use the engine format.

## Simulator parity

Sim `practice_*` tables received:
- Missing identifier columns added where absent (`document_ref`, `pid_reference`, `brief_reference`, etc.)
- AFTER INSERT triggers wired to matching `sim.*` admin rules
- Legacy sim-only generators retired: `generate_sim_mandate_reference_trigger`, `generate_sim_portfolio_code`, `generate_practice_business_case_reference`

## Verification checklist

1. Apply SQL files in order (admin v155/v156 first).
2. Create a **Risk** via Platform UI — confirm `risk_identifier` matches `R-YYYY-NNN` pattern.
3. Create second risk in same register — sequence increments.
4. Create risk in different register — sequence resets to `-001`.
5. Repeat smoke test for Issues and one report type.
6. Create **form instance** — confirm `instance_reference` populated.
7. Admin list page shows **Sequential** badges on migrated rules.
