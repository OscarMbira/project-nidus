# v836 — Remove "PMBOK" from process_template content tables (public + sim)

## Goal
Third and final wave of the PMBOK naming-compliance sweep this session. Companion Admin-repo
fixes (`v199`/`v200` in `project-nidus-admin/SQL`) handled `admin.global_template_library`
display names. This wave fixes the thing explicitly flagged and asked for: the
**process_template content tables themselves** —
`public.project_charters` (+ 23 sibling tables)'s own demo/seed rows, which are a completely
separate system from `global_template_library` (this is the ~24-table polymorphic domain
already flagged as out-of-scope for the earlier Standards-Based clone work, `v827`/`v197`
plans — this fix doesn't touch that risk area, it only renames text in an existing, already
narrowly-scoped demo seed).

## Found
- `public.project_charters` (and 23 sibling `process_template` tables) seeded by
  `SQL/v633_process_templates_master_seed_data.sql` (public) /
  `v634_sim_process_templates_master_seed_data.sql` (sim), generated by
  `scripts/generate-v633-process-templates-seed.mjs`.
- Every one of the 24 seeded rows' `document_data` JSONB had a `"pmbok_group"` key.
- The `project_charters` row's `description` column read "Standard PMBOK project charter for
  authorising a new project or phase.".
- `v635_sim_process_templates_sidebar_menu.sql`'s `sim_pmo_process_templates_section` menu item
  had `menu_description = 'Simulator PMO — PMBOK process templates hub'`.
- No frontend/application code reads the `pmbok_group` key (confirmed via repo-wide grep — only
  the SQL seed files and the generator script referenced it), so renaming it is safe.

## Design
1. **Source fix** — edited `scripts/generate-v633-process-templates-seed.mjs` (the description
   text, the `pmbok_group` → `standards_based_group` key, and the sim menu description), then
   re-ran it to regenerate `v633`/`v634`/`v635` in place. Diffed the regeneration
   (`git diff --ignore-space-at-eol`) to confirm only the intended ~51 lines changed across the
   three files — no unintended reformatting or content loss.
2. **Live-data fix** — new `SQL/v833_pmbok_process_template_content_naming_compliance_fix.sql`:
   loops over the same 24 table names (public schema, `reference_code LIKE 'SEED633-%'`; sim
   schema, `'SEED634-%'`), renaming the `pmbok_group` JSONB key to `standards_based_group` via
   dynamic `EXECUTE format(...)` (safe here — table names come from a fixed in-file array, never
   user input), fixes `project_charters.description`, and fixes the one live
   `menu_items.menu_description` row if it still has the old text.

## Explicitly out of scope
- Any other domain's copy/clone work — this is a rename-in-place on existing rows only, not new
  content generation, so none of the risk that kept `process_template` out of the earlier
  Standards-Based clone (`v827`/`v197`) applies here.
- An older platform-side (non-sim) menu description, `'PMBOK-aligned process templates hub (Pre-
  Project + 5 process groups)'`, found in `v629_process_templates_sidebar_menu.sql` /
  `v666_process_templates_sidebar_menu.sql`. Not fixed — `v718_dissolve_process_templates_section.sql`
  later restructured/re-parented this section, so this session can't confirm without live DB
  access whether that specific menu row (and its description text) is even still active. Flagged
  as a residual follow-up, not silently dropped.
